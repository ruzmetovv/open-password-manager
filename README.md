# oPass 3.2 — исправления карт, логотипы и производительность

Обновление oPass 3.1 (Chromium / Helium). Исходная структура хранилища **не меняется**: `vault` и `cardsVault` остаются зашифрованными с помощью AES-256-GCM и PBKDF2-SHA-256, 310 000 итераций.

## Что изменено

1. **Исправлен год действия карты:** если форма содержит отдельное поле `YY` длиной 2 символа, вводится `27`, а не `2027` (ранее некоторые формы оставляли `20`). Поддержаны `MM/YY`, `MM/YYYY`, поля с `maxlength=4/5/6`, отдельные `MM` и `YY/YYYY`, а также выпадающие списки месяца и года. Тестировались сценарии `07/27` в форме с `YY`, `YYYY`, `select` и объединённым полем.
2. **Логотипы сайтов:** вместо одинаковых значков-ключей используется favicon сайта из **встроенного локального хранилища значков Chromium**. Если значок доступен в момент открытия окна расширения, oPass пытается сохранить его небольшую PNG-копию внутри **зашифрованного** хранилища паролей. При новых сохранениях также пытается получить и зашифровать favicon с текущей страницы, если она разрешает безопасное чтение изображения. Благодаря этому доступные значки синхронизируются с паролями. Когда сайт не предоставляет изображение или браузер его не знает, показывается буква сайта — гарантировать логотип для любого домена технически невозможно без внешней загрузки.
3. **Логотипы карт:** пять локальных SVG-значков Visa, Mastercard, American Express, Discover и JCB входят непосредственно в расширение, работают без сети; банковский эмитент (например, Revolut) автоматически не определяется.
4. **Понятные кнопки:** «⧉ Логин» копирует логин, «⧉ Пароль» копирует пароль, ✎ редактирует, × удаляет. В разделе карт кнопка «↗ Заполнить»; элементы доступны по подсказкам при наведении.
5. **Производительность:** поиск с задержкой 90 мс, меньше повторных запросов к `chrome.storage` при вводе и фокусе, анализ полей карты один раз за событие, синхронизация не стартует заново для каждой операции. Локальные изменения синхронизируются по расписанию с объединением запросов примерно через 30 секунд; принудительная синхронизация вручную доступна сразу.

## Обязательно сделайте резервную копию перед обновлением

1. В текущем oPass откройте **Настройки → Экспорт JSON**. Сохраните файл и проверьте, что он не пустой.
2. Скопируйте текущую папку расширения отдельно — **не удаляйте старое расширение**.
3. Если расширение установлено через «Загрузить распакованное», замените файлы в **той же папке**, затем на странице `chrome://extensions` нажмите **Обновить / Reload** (для Helium используйте страницу расширений вашего браузера).
4. Если установить архив как отдельное расширение, оно может получить **другой ID и пустое хранилище**. Для переноса данных в таком случае понадобится зашифрованная резервная копия.
5. Проверьте тестовой картой, что год заполняется как `27`, а затем проверьте реальные сайты. Форма банка или платёжного провайдера может быть устроена нестандартно, в том числе через изолированный iframe.

## Синхронизация Google Drive

Используется тот же OAuth-клиент и тот же файл `appDataFolder/vault.json`, в котором хранятся **зашифрованные** `vault` и `cardsVault`. Новые фавиконки сайтов хранятся *внутри* зашифрованных записей с паролями, поэтому синхронизируются вместе с ними.

**Изменение:** автоматическая синхронизация теперь отложенная (~30 секунд), чтобы не открывать окна Google и не нагружать браузер при каждом сохранении. После запуска браузера или при необходимости войти в Google выберите **↻ синхронизировать вручную**; автоматические операции больше не вызывают интерактивное окно OAuth. Синхронизация с вашим реальным Google-аккаунтом здесь не проверялась.

## Безопасность

Необязательное CVV/CVC сохраняется вместе с картой в зашифрованном `cardsVault`, как было в 3.1. **Хранение CVV рискованно даже при AES-256-GCM:** злоумышленник с доступом к разблокированному браузеру, вредоносное расширение или вредоносный сайт может получить данные при заполнении. В промышленных платёжных системах PCI DSS запрещает хранение CVV после авторизации, даже в зашифрованном виде. Рекомендуем не сохранять CVV; не размещайте открытые резервные копии в общедоступных местах.

## Тестирование и ограничения

- **Проверено программно:** синтаксис JS, шифрование/дешифрование тестовых записей, работа полей `YY`, `YYYY`, `select` и `MM/YY` в Chromium с тестовой страницей, а также визуальная проверка CSS-интерфейса.
- **Не проверено в установленном Helium:** настоящие платёжные формы, чтение favicon в Helium, OAuth Google Drive, работа иконок банковских систем на всех экранах. Браузерная среда тестирования не разрешает открывать страницы и устанавливать расширения напрямую.
- Логотипы сайтов кэшируются, когда они реально доступны; при отсутствии favicon используется текстовая иконка.
- Платёжные поля в недоступных cross-origin iframe / shadow DOM могут не заполняться. oPass не обходит защиту платёжных провайдеров.
- Для синхронизации используется API Google Drive с ранее настроенным OAuth-клиентом оригинального расширения.

## Файлы

- `manifest.json`: Manifest V3, версия 3.2.0
- `crypto.js`: совместимое AES-256-GCM + PBKDF2
- `background.js`: локальное шифрование и синхронизация Google Drive
- `content.js`: автосохранение и автозаполнение
- `popup.html`, `popup.js`: тёмный интерфейс oPass
- `icons/`: иконка расширения
- `assets/cards/`: офлайн-значки платёжных систем


## Исправления 3.2.1
- Убрано наложение букв-заглушек на favicon: значок отображается целиком, а буква показывается только при отсутствии favicon.
- Немного уменьшена высота записей паролей и улучшены кнопки копирования (видимая иконка двух листов + подпись).
- Без изменений в форматах зашифрованного хранилища и Google Drive.
- Перед обновлением рекомендуем сохранить зашифрованную резервную копию.

Обновление без удаления: распакуйте в ту же папку, замените файлы и нажмите «Обновить» в панели расширений Helium. Используйте тестовые данные для проверки новой версии.
